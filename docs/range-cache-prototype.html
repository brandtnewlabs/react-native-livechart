Implemented on a branch based on main. No new public prop or dependency. This is separate from automatic sleep: the animation loop keeps running.

What gets reused?

  1. Each notified history change creates a new revision token. Replacing an array or using .modify() invalidates the result, even if the array length stays the same.
  2. Binary searches find the visible start and end indices. Small movements inside the same index bounds reuse the previous low/high and their timestamps.
  3. The live candle, animated value, reference lines, threshold and gap anchors are folded in each frame. Then the normal range animation runs.

Line and candle history have separate revisions. The cache stores one result per engine. It is deliberately conservative: any history edit invalidates the result, including edits outside the viewport.

A native issue caught and fixed: the reveal bridge can forward the same array and suppress its notification. Revision tracking now also observes the original source. Static charts use that revision too, so interior edits refresh their range.

A much harder live-chart test

Open Volatile range stress on the demo app home screen. It targets 30 updates per second, keeps 6,000 rolling points, and includes live candles, forced spikes to 400, crashes to 8, pause/resume, zoom, and interior history corrections.

This test found a real bug: the first run had 21 mismatches in 2,983 frames. An in-place edit could change the array before a derived revision mapper ran. Revision invalidation now happens synchronously inside the SharedValue notification, including notifications from the original feed.

After the fix: 12,966 frames, zero mismatches. That includes 6,930 line frames and 6,036 candle frames. Every actual engine tick was compared against a fresh uncached calculation using the same input and pre-tick state. All output fields matched.

The temporary on-screen comparison counter shown in the recording has been removed from the normal demo and library. It added extra work, so this recording proves correctness in the tested scenarios, not a CPU or FPS improvement. A regression test now ticks immediately after an in-place notification without flushing derived mappers.

Scope and limits

  • Single-series LiveChart line and candle history only. Multi-series calculations and future indicators are unchanged.
  • No new settings or consumer migration. Data changes must notify the SharedValue; silent nested mutation cannot reliably notify consumers.
  • Cache misses still scan visible history. Very fast feeds may get little benefit.
  • Physical-device, Android and release-build performance have not been measured.

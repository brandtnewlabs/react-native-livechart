Now integrated in the production hook

useCandlePaths now calls buildCandleBodyPath for its up/down body batches. Each call reuses one local plain rectangle for its sharp bodies. Rounded bodies keep their existing commands. Wicks, volume, geometry, clipping and the four batched paths retain their behavior.

The rectangle is created inside each worklet invocation. This removes per-candle rectangle factory calls without retaining mutable scratch across React and UI runtimes. Each builder still returns a fresh immutable path with detach(), so updates repaint normally. No new public prop or dependency is needed.

What changed, and what did not?

  1. Main: calculate body/wick objects, then scan them four times to fill the up/down paths. Sharp bodies also call Skia.XYWHRect for each rectangle.
  2. One pass: calculate each candle once and immediately fill the same four builders. Reuse a rectangle and rounded-rectangle input. No body/wick arrays are needed.
  3. Rect reuse only: keep the geometry objects and all four scans. Replace per-candle XYWHRect calls with one mutable plain rectangle input.

For sharp candles, rectangle reuse alone is almost as fast as the one-pass version. For rounded candles, neither change produces a large win. The initial geometry-only timing was roughly 13% of the baseline rebuild time; the rest included builder calls and detach work. This argues against treating the repeated TypeScript scans as the main bottleneck.

The one-pass version removes two geometry objects per visible candle, plus per-candle rectangle input wrappers. Rectangle-only reuse keeps the geometry objects but removes the sharp rectangle factory calls. These are structural allocation counts from the code, not measured heap or GC savings. Native Skia still allocates its own path data.

All versions keep four immutable path outputs and four batches. Body/wick drawing commands and clipping order stay the same. Volume, gaps and scrub focus are unchanged. The production hook now uses only the rectangle-reuse approach. Current main already uses reusable PathBuilder instances and detach(); this experiment preserves that lifecycle.

Scope and next step

This work starts from main and stays separate from the history-cache and automatic-sleep PRs. The production hook now reuses sharp-body rectangle inputs. There is no new public prop, dependency or native module. The production change, reproducible benchmark, tests and documentation are included together for review.

The smaller change is implemented in useCandlePaths and validated in the complete simulator demo. Physical-device and release-build frame time and memory retention remain unmeasured. Dense charts show a useful isolated saving; ordinary 40-candle charts save only around 0.04–0.05 ms per rebuild.

A native helper would add build and maintenance cost. First establish that candle construction is a major part of real app frame time after the smaller change. Android and web performance have not been measured.

What changed

  1. Reuse rectangles for volume bars. Each color batch uses one plain rectangle input for sharp bars. Skia copies its coordinates immediately. Rounded bars keep their rounded commands.
  2. Keep the historical maximum until it is invalid. The production hook watches candle data notifications and the first/last visible indices. Scrolling a little within the same buckets does not trigger another history scan. Changing an existing candle does—even if the array length and identity stay the same. Live volume is folded in separately, so a live outlier still rescales the bars.
  3. Calculate each curve once. A segment’s slopes, tangents and control points feed the separate line, fill and optional threshold builders. Gaps keep separate contours. If only the threshold changes, existing line/fill outputs are retained.

No new public props, dependencies or native module. Immutable path outputs and batched drawing remain in place. The one-pass candle experiment stays separate.

Checks beyond the video

  • 540 native path comparisons, zero mismatches. Old and new native SVG path output matched with changing viewport edges, live volume outliers, historical volume edits and line endpoints.
  • 240 native cache checks, zero mismatches. The actual Reanimated hook matched an uncached maximum through fractional scrolling, same-object edits, a falling maximum, pan, width changes, empty history and replacement.
  • Scan counter audit: eight scans across that probe; only one during the initial 30-frame fractional glide. These are measured scan counts, not an inferred FPS gain. Temporary counters were removed before final timing.
  • 114 native threshold-only retention checks, zero mismatches. Line and fill kept their output references while the threshold moved, including after data changes and empty/restore.
  • Automated regression coverage: cached geometry versus frozen baseline; inclusive window edges; same-length maximum changes; exact curve and fill commands across gaps, duplicate X positions, spikes, two-point segments, linear/smooth modes and sampled/constant thresholds.
  • Verification: 120 suites; 1,705 tests passed, five skipped. Typecheck, lint and library build passed. React Doctor: 100/100, including new untracked source files.

How to read these numbers

The baseline code is preserved under demo-lib/performance-baseline/ from commit 2a512fc. Initial baseline-only timings were collected before modifying the library. Final comparisons run both versions in the same UI runtime to reduce differences between launches.

Each variant gets 20 warm-ups, then nine rotated rounds of 40 rebuilds. Volume uses 6,000 stored candles and roughly 40, 200 or 1,000 visible candles; lines use those point counts. Timings include geometry, builder calls and detach. The cache-hit variant includes bound lookup and cached maximum use. The rectangle-only variant rescans each rebuild, representing the construction cost when the cache misses.

Excluded: engine work, mapper scheduling, React, GPU drawing and whole-app frame time. Cache invalidation itself is checked separately in the real derived-value graph. The screen briefly blocks during benchmark loops; those stalls are intentional and are not a chart regression.

Device: dedicated iPhone 17 Pro simulator, iOS 26.5, development build. Agent-device reports frame-hitch sampling unavailable on simulators. Physical-device release builds, Android/web timings and long-run memory still need separate measurements. Small differences in rounded bars or cache-only rows should not be treated as established performance gains.
